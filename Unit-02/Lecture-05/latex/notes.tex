\section{Lecture Overview}
This lecture moves from basic function syntax to advanced usage patterns that
appear in real codebases:
\begin{itemize}
  \item passing collections safely (mutation vs copying),
  \item recursion (and how to avoid infinite recursion),
  \item functional tools: \texttt{map}, \texttt{filter}, and \texttt{lambda},
  \item closures (functions defined inside functions), and
  \item pure functions vs side effects.
\end{itemize}

\section{Types of Functions in Python (and When to Use Them)}
In Python, a \textbf{function is an object}. That means you can store a function
in a variable, pass it into another function, and return it from a function.
This idea is the foundation of \textbf{functional patterns} such as
\texttt{map}/\texttt{filter} and closures.

\subsection{Built-in Functions (Provided by Python)}
Python already includes many reliable, well-tested functions. Prefer built-ins
when they solve the problem clearly and directly.
\begin{itemize}
  \item \textbf{Numeric/aggregation:} \texttt{sum}, \texttt{min}, \texttt{max}
  \item \textbf{Sizes and membership:} \texttt{len}, \texttt{any}, \texttt{all}
  \item \textbf{Ordering:} \texttt{sorted} (returns a new list)
  \item \textbf{Type conversion:} \texttt{int}, \texttt{float}, \texttt{str}, \texttt{list}
\end{itemize}
\textbf{Use case example:} reporting a quick summary without writing a loop:
\begin{lstlisting}[language=Python]
marks = [72, 81, 65, 90]
print(min(marks), max(marks), sum(marks) / len(marks))
\end{lstlisting}

\subsection{User-Defined Functions (\texttt{def})}
You write a function when you want to \textbf{reuse logic}, \textbf{name an idea},
and \textbf{reduce repetition}. A good function usually does one job and has a
clear input/output contract.
\begin{itemize}
  \item \textbf{Prefer returning values} instead of printing inside the function.
  \item \textbf{Document side effects} (e.g., mutating a list argument).
\end{itemize}
\begin{lstlisting}[language=Python]
def average(nums):
    return sum(nums) / len(nums)
\end{lstlisting}

\subsection{Functions by Arguments and Return Value (Common academic view)}
You may see functions classified as ``types'' based on whether they take input
arguments and whether they return a value. This is a useful mental model.
Important Python detail: \textbf{every function returns something}. If you do
not write \texttt{return}, Python returns \texttt{None} automatically.
\begin{itemize}
  \item \textbf{No arguments, no (useful) return:} often used for side effects (printing).
  \item \textbf{Arguments, no (useful) return:} often used to update something (mutating a list, writing a file).
  \item \textbf{No arguments, returns a value:} usually reads from elsewhere (global state, user input). Use carefully.
  \item \textbf{Arguments, returns a value:} most reusable style; can be pure and easy to test.
\end{itemize}
\begin{lstlisting}[language=Python]
def greet():
    print("Hello")        # returns None

def add_item(lst, x):
    lst.append(x)         # returns None (mutates input)

def get_pi():
    return 3.14159

def area_circle(r):
    return 3.14159 * r * r
\end{lstlisting}

\subsection{Function Parameter Styles (Practical Python)}
Real Python code often uses different parameter styles to make APIs flexible and readable.
\begin{itemize}
  \item \textbf{Positional arguments:} simplest and most common.
  \item \textbf{Keyword arguments:} improve readability and reduce ordering mistakes.
  \item \textbf{Default values:} make parameters optional (configuration-style).
  \item \textbf{Variable-length arguments:} \texttt{*args} (many positional) and \texttt{**kwargs} (many keyword).
  \item \textbf{Keyword-only arguments:} force clarity (parameters after \texttt{*} must be named).
\end{itemize}
\begin{lstlisting}[language=Python]
def power(base, exp=2):
    return base ** exp

print(power(5))            # 25 (default exp=2)
print(power(base=2, exp=5))# 32 (keyword arguments)

def mean(*nums):
    return sum(nums) / len(nums)

def clip(x, *, lo=0, hi=100):
    return max(lo, min(x, hi))
\end{lstlisting}

\subsection{Anonymous Functions (\texttt{lambda})}
\texttt{lambda} creates a small function without a name. It is best when the
function is \textbf{short}, \textbf{used once}, and the meaning is obvious from
context.
\begin{itemize}
  \item \textbf{Good use case:} \texttt{key=} in \texttt{sorted}, small transforms in \texttt{map}
  \item \textbf{Avoid when:} logic becomes complex (use \texttt{def} for readability)
\end{itemize}
\begin{lstlisting}[language=Python]
words = ["pear", "banana", "fig"]
print(sorted(words, key=lambda w: len(w)))  # key function
\end{lstlisting}

\subsection{Higher-Order Functions (Functions that take/return functions)}
A \textbf{higher-order function} either:
\begin{itemize}
  \item takes a function as input (e.g., \texttt{map}, \texttt{filter}, \texttt{sorted(key=...)}), or
  \item returns a function as output (a function factory / closure).
\end{itemize}
\textbf{Use case:} customize behavior without rewriting the whole algorithm.
\begin{lstlisting}[language=Python]
nums = [1, 2, 3, 4]
sq = list(map(lambda x: x * x, nums))           # transform
ev = list(filter(lambda x: x % 2 == 0, nums))   # select
\end{lstlisting}
\textbf{Use case (returning a function):} create a specialized function:
\begin{lstlisting}[language=Python]
def make_multiplier(k):
    def mult(x):
        return x * k
    return mult
\end{lstlisting}

\subsection{Predicate Functions (Return \texttt{True}/\texttt{False})}
Predicates are commonly used with \texttt{filter}, \texttt{any}, and \texttt{all}.
Their job is to \textbf{decide}, not to compute a numeric result.
\begin{lstlisting}[language=Python]
def is_valid_mark(x):
    return isinstance(x, int) and 0 <= x <= 100

marks = [95, None, 120, 70]
valid = list(filter(is_valid_mark, marks))
\end{lstlisting}

\subsection{Key Functions (Used for Sorting/Ranking)}
Key functions are used by \texttt{sorted}, \texttt{min}, and \texttt{max}. They
define what ``comparison'' should mean in your problem.
\begin{lstlisting}[language=Python]
students = [("A", 9.1), ("B", 8.3), ("C", 9.4)]
top = max(students, key=lambda t: t[1])  # compare by CGPA
\end{lstlisting}

\subsection{Recursive Functions (Define a problem in terms of itself)}
Recursion is a natural fit when a problem breaks into smaller subproblems of the
same shape.
\begin{itemize}
  \item \textbf{Good use cases:} tree traversal, nested structures, divide-and-conquer
  \item \textbf{Be careful:} recursion depth limit, call overhead in Python
\end{itemize}
For simple loops, prefer iteration (clearer + faster in Python).

\subsection{Generator Functions (\texttt{yield}) (Lazy computation)}
Generators produce values one at a time instead of building a full list in memory.
\textbf{Use case:} large data, streaming, pipelines.
\begin{lstlisting}[language=Python]
def count_up_to(n):
    i = 1
    while i <= n:
        yield i
        i += 1

for x in count_up_to(3):
    print(x)
\end{lstlisting}

\subsection{Pure vs Side-Effect Functions (Engineering viewpoint)}
\begin{itemize}
  \item \textbf{Pure:} no external changes; easy to test; good for reuse and composition
  \item \textbf{Side effects:} printing, file I/O, mutating arguments; necessary but should be controlled
\end{itemize}
In practice, aim for \textbf{pure core logic} and keep side effects at the edges
(input/output layer).

\subsection{Mutating vs Non-Mutating APIs (Important for Lists/Dicts)}
Some operations \textbf{modify objects in place} (side effect), while others
return a \textbf{new object}.
\begin{itemize}
  \item \texttt{items.sort()} mutates the list
  \item \texttt{sorted(items)} returns a new list (original is unchanged)
\end{itemize}
This lecture's next section shows why this distinction matters when passing
collections into functions.

\section{Passing Collections: Mutation and Side Effects}
Lists and dictionaries are mutable. When you pass them into a function, you pass
\emph{a reference to the same object}. That means the function can change the
caller-visible object.

\subsection{In-place Mutation (Sometimes Useful)}
\begin{lstlisting}[language=Python]
def add_item(lst, item):
    lst.append(item)

data = [1, 2]
add_item(data, 99)
print(data)  # [1, 2, 99]
\end{lstlisting}
This can be efficient, but it is also a side effect. If a function mutates its
inputs, it should be clearly documented (and ideally reflected in the name).

\subsection{Avoiding Unintended Mutation (Copying)}
If you want a function that behaves like ``input in, output out'' without
changing input, copy first:
\begin{lstlisting}[language=Python]
def sort_copy(items):
    tmp = items.copy()
    tmp.sort()
    return tmp
\end{lstlisting}
This pattern is a stepping stone to writing \textbf{pure functions}.

\section{Recursion}

\subsection{What Is Recursion?}
A recursive function calls itself to solve a smaller version of the same
problem.
Two required parts:
\begin{itemize}
  \item \textbf{Base case:} stops recursion.
  \item \textbf{Progress step:} reduces the problem size each call.
\end{itemize}

\subsection{Example: Factorial}
\begin{lstlisting}[language=Python]
def factorial(n):
    if n == 1:
        return 1
    return n * factorial(n - 1)
\end{lstlisting}
If the base case is missing or never reached, Python raises a
\texttt{RecursionError} after hitting the recursion depth limit.

\subsection{When to Avoid Recursion in Python}
Recursion is sometimes the clearest solution (trees, divide-and-conquer), but
for simple loops Python iteration is usually:
\begin{itemize}
  \item faster (less call overhead),
  \item safer (no recursion depth risk), and
  \item easier to debug.
\end{itemize}

\section{Functional Tools: \texttt{map}, \texttt{filter}, \texttt{lambda}}

\subsection{\texttt{map}: Transform Each Item}
\texttt{map(f, iterable)} applies \texttt{f} to each item.
\begin{lstlisting}[language=Python]
nums = [1, 2, 3, 4]
squares = list(map(lambda x: x * x, nums))
\end{lstlisting}

\subsection{\texttt{filter}: Keep Items That Match a Condition}
\texttt{filter(pred, iterable)} keeps items where \texttt{pred(item)} is true.
\begin{lstlisting}[language=Python]
nums = [1, 2, 3, 4]
evens = list(filter(lambda x: x % 2 == 0, nums))
\end{lstlisting}

\subsection{Pitfall: Iterators in Python 3}
In Python 3, \texttt{map} and \texttt{filter} return \textbf{iterators}, not
lists. That is why we wrap them in \texttt{list(...)} when printing or reusing.

\subsection{\texttt{lambda}: Small Anonymous Functions}
\texttt{lambda} is useful for short functions used once, often as a \texttt{key}
for sorting or as a mapping function.
Example (sorting by length):
\begin{lstlisting}[language=Python]
words = ["pear", "banana", "fig"]
print(sorted(words, key=lambda w: len(w)))
\end{lstlisting}
If the lambda becomes complex, define a normal named function instead.

\subsection{Inner Functions and Closures}
An inner function can capture variables from the outer function.
\begin{lstlisting}[language=Python]
def make_multiplier(k):
    def mult(x):
        return x * k
    return mult

triple = make_multiplier(3)
print(triple(10))  # 30
\end{lstlisting}
This is a closure: \texttt{mult} ``remembers'' \texttt{k}.

\subsubsection*{Encapsulation with Inner Functions}
Inner functions are also useful for \textbf{encapsulation}: keeping helper logic
private so it cannot be called incorrectly from outside.
\begin{lstlisting}[language=Python]
def normalize_marks(marks):
    def clip(x):
        return max(0, min(x, 100))
    return [clip(m) for m in marks]
\end{lstlisting}
Here, \texttt{clip} is an internal helper used only inside
\texttt{normalize\_marks}. This keeps the public API small and focused.

\section{Pure Functions vs Side Effects}
\textbf{Pure function:}
\begin{itemize}
  \item same input always gives same output, and
  \item no changes to external state (no mutation of input, no global writes).
\end{itemize}
Pure functions are easier to test and reason about. Side effects are sometimes
necessary (writing a file, printing, updating a database), but should be kept
controlled.

\section{Quiz and Solutions}

\subsection{Checkpoint 1 (Base Case)}
\textbf{Question.} Identify the base case in a recursive function. Why is it
necessary?

\textbf{Solution.} The base case is the condition that stops recursion (e.g.,
\texttt{if n == 1: return 1} in factorial). Without it, the function would call
itself forever (until Python raises \texttt{RecursionError}).

\subsection{Checkpoint 2 (Replace Loop with \texttt{map})}
\textbf{Question.} Replace this loop with \texttt{map}:
\begin{lstlisting}[language=Python]
nums = [1,2,3,4,5]
squares = []
for n in nums:
    squares.append(n*n)
\end{lstlisting}

\textbf{Solution.}
\begin{lstlisting}[language=Python]
nums = [1, 2, 3, 4, 5]
squares = list(map(lambda x: x * x, nums))
\end{lstlisting}

\subsection{Think-Pair-Share (Avoiding Recursion)}
\textbf{Prompt.} When should you avoid recursion in Python? Provide one reason
and one example.

\textbf{Sample response.} Avoid recursion for simple counting/accumulation loops
because recursion is slower and can hit recursion depth limits. Example:
summing a list is clearer and safer with a \texttt{for} loop than with recursion.

\subsection{Exit Question (Mutation Visibility)}
\textbf{Question.} If a function appends to a list passed as an argument, does
the caller see the change? Why?

\textbf{Solution.} Yes. The function receives a reference to the same list
object, so mutating it (append/remove) changes the object the caller holds.

\subsection{Exercise 2: Recursive Sum}
\textbf{Task.} Write a recursive function \texttt{sum\_list(nums)}.

\textbf{Solution.}
\begin{lstlisting}[language=Python]
def sum_list(nums):
    if not nums:
        return 0
    return nums[0] + sum_list(nums[1:])
\end{lstlisting}
Note: slicing creates new lists; for very large lists, an iterative approach is
more efficient.

\subsection{Exercise 3: Rewrite \texttt{map/filter} as a Comprehension}
\textbf{Task.} Given \texttt{nums}, build a list of squares of even numbers.

\textbf{Solution.}
\begin{lstlisting}[language=Python]
nums = [1, 2, 3, 4, 5]
even_squares = [n*n for n in nums if n % 2 == 0]
\end{lstlisting}

\subsection{Exercise 4: Closure Practice}

by 5.

\textbf{Solution.}

print(five_x(7))  # 35
\end{lstlisting}
